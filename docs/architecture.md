# Orbit architecture — local release candidate, 2 October 2026

Orbit remains a static, dependency-free browser application. GitHub Pages serves the shell; browsers talk directly to reviewed test operators and RIPEstat and persist history locally. There is no Orbit backend, paid API, user-account database, remote telemetry collector or bandwidth proxy. The local modifications are not deployed.

![Architecture](orbit-architecture.svg)

The [Mermaid source](orbit-architecture.mmd), [SVG](orbit-architecture.svg) and [PNG](orbit-architecture.png) are logical responsibility diagrams. Read the contracts below for exact implementation behavior.

| Boundary | Implementation and contract |
| --- | --- |
| UI | `index.html`, `styles.css`, `ui.js`: Overview, Telemetry, History, measured graphs, scrubber, route selection, readiness explanations and all existing exports |
| Coordinator | `app.js`: filtered discovery, bounded GET requests, metadata, preflight, idle/loaded RTT, wall-time aggregate transfers, cancellation, retry/recovery and persistence |
| Calculation | `core.js` and `telemetry.js`: medians, interpolated percentiles, jitter, readiness heuristics, phase-aware exports and grades; shared helpers can also be tested as Node modules |
| Trust boundary | `security.js`: exact reviewed HTTPS paths, no redirects/credentials/referrers, 1 MiB JSON and 17 MiB binary response caps, enum/schema validation |
| Local persistence | IndexedDB `orbit-speed-test`, version 1, store `tests`, key `id`; schema unchanged, history versions 1/2/3 accepted; no IP/ISP/ASN/city fields |
| Offline shell | `sw.js`, `pwa.js`, manifest/icons: exact local GET assets, scope-specific cache/version, normal waiting-worker lifecycle; external requests and all uploads bypass cache |
| Catalog | Same-origin `servers.json` only, constrained by the compiled endpoint allowlist; no live catalog merge or device geolocation |
| Delivery | Pinned Actions: artifact/unit/coverage/SCA/SBOM, three-browser tests, Gitleaks/Semgrep/CodeQL, deterministic archive provenance, then Pages deployment. New CI is pending an approved push and actual GitHub execution. |

## Measurement and failure contracts

1. Discovery filters operators before probing. Normal mode samples up to eight candidates; expanded mode includes every reviewed candidate, capped at 40. Each probe has an 800 ms timeout. Failed endpoints remain unavailable, including an unavailable Cloudflare edge. Distance is an optional manual city-center preference, never GPS.
2. Launch obtains an origin-scoped Web Lock when supported, preventing cooperating tabs from contaminating each other's tests. It creates a running record, refreshes stale metadata, and checks both download and upload contracts before measuring.
3. Idle RTT uses a GET warm-up and ten complete bounded GET responses to the selected endpoint. All samples, including slow tails, remain in order. Optional detailed Resource Timing provides an HTTP first-byte median only when exposed; no STUN or fictitious pure wire measurement is performed.
4. The active profile schedules download/upload for 5 or 15 seconds each with one or three workers. Completed payload bits are divided by the single full phase wall clock, including stalls/retries. Each phase has a nominal target + 20 seconds drain deadline, subject to browser scheduling. Each transfer allows one smaller retry; 401/403/404/429 are terminal for that transfer. Requests, probes and a shared 8 GB planned-payload budget remain bounded.
5. Loaded RTT uses the same GET/body consumption method as idle RTT, with a 200 ms pause between requests. Deltas use the idle sample median. Sparse worst-direction samples cannot earn a bufferbloat grade; readiness is explicitly a route-specific heuristic.
6. Automatic mode can retry the entire test on one other reachable, filter-matching endpoint; each attempt gets its own record. Manual selection never switches. Cancellation, rate limits and safety stops prevent recovery. Partial phase data is retained but does not receive completed-flight headlines or quality ratings.
7. History open/transactions have a 3-second timeout and failures leave exportable session records. Late database opens are closed, version changes close obsolete handles, and failed opens can be retried. Closing a tab can still leave a deliberately labelled unfinished record.

## Data and privacy

| Data | Lifetime and external flow |
| --- | --- |
| Generated test payloads | Browser ↔ selected public operator; binary downloads counted and discarded; uploads contain generated bytes |
| Public IP/ASN/registered network holder | Current tab memory/UI only; Cloudflare headers or RIPEstat IP/ASN lookup; absent from history/exports |
| Manual city preference | Current tab memory only; local shortlist sorting; never transmitted |
| Access type | Enum, manual/browser/unavailable source and performance class saved in the flight; no SSID or inferred radio generation |
| History and exports | IndexedDB plus explicit local downloads/clipboard; no automatic synchronization or result upload |

GitHub project sites share an origin with other applications under the same account. Treat those applications and browser extensions as separate trust boundaries. A dedicated hosting origin is recommended for stronger isolation. User-local records are convenience data, not authenticated measurement evidence.

No availability guarantee follows from third-party reachability. The provider/hosting review, threat model, operational targets, release rings and rollback steps are in [launch-readiness.md](launch-readiness.md).
