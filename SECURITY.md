# Security review — October 2, 2026

Orbit is a static browser application. This review and its regression tests reduce specific risks; they are not an independent penetration-test certification or a promise of zero vulnerabilities.

## Controls checked or added

- Remote catalogs can only select exact HTTPS endpoints in `dist/security.js`. New hosts or paths require a reviewed code change. Credentials, arbitrary ports, private addresses, unexpected paths, and cross-origin server paths are rejected; fetch redirects fail closed.
- The HTML content security policy permits only local scripts/styles and reviewed connection origins. Inline scripts, eval, plugins, forms and frames created by Orbit are disabled. Manifest and worker sources are restricted to self; the only named Trusted Types policy accepts the exact local `sw.js` URL. Trusted Types protects script injection sinks in supporting browsers. All external text is rendered as text, not HTML.
- JSON responses are limited to 1 MiB before parsing. Binary responses are streamed and discarded after counting, capped at 17 MiB per response. Tests also have per-request timeouts, bounded stream counts (1 or 3), request/sample limits and a shared 8 GB planned-payload safety budget per invocation, including retry/recovery attempts. Automatic recovery tries at most two reviewed endpoints; cancellation and budget stops do not retry. Cloudflare download requests use a conservative 8 MB cap; Clouvider uploads cap at 1 MB to avoid the reproduced upstream body-size rejection. They are not a bandwidth-billing guarantee.
- IP/ASN/edge metadata and saved history are validated before use. Unknown history fields, oversized arrays, invalid dates, and non-finite/extreme measurements are rejected. Bad records are ignored without deleting stored data. History never intentionally includes IP, location, ISP name, SSID, credentials, or personal files. Network snapshots allow only enum values and a Data Saver boolean; cellular generation labels require a manual source.
- Page load runs parallel, 800 ms-bounded server-discovery probes and resolves IP / ISP via Cloudflare and RIPEstat (including the exact reviewed whats-my-ip fallback). Sustained bandwidth tests still require pressing Start Test. Orbit does not use the Geolocation API, request browser location permission, or transmit route-preference coordinates. Requests omit credentials and referrers.
- When embedded, the app refuses network operations and does not load history. This is a fallback, not a replacement for a `frame-ancestors` response header.
- The local server binds to loopback, accepts only approved Host/Origin values, serves a fixed asset list, and refuses uploads, directory listings, and non-GET/HEAD methods. It supplies CSP including `frame-ancestors 'none'`, DENY framing, nosniff, a restricted Permissions Policy, no-referrer, and same-origin isolation headers.
- GitHub Actions use immutable commit pins, no persisted checkout credentials, read-only verification permissions, and deployment-only Pages/OIDC permissions. Pull requests are tested but cannot deploy. Only `dist` becomes the Pages artifact; no local records or development files are published.

- The service worker handles only GET requests for an exact list of same-origin app assets. All third-party requests, test transfers, metadata, POST bodies and unrelated paths bypass it. Precache requests omit credentials and reject redirects; they commit as one batch. Cache cleanup is restricted to Orbit’s exact directory prefix, never other applications or IndexedDB history. Updates use the standard worker lifecycle and never force activation or page reload during measurements.
- The manifest uses a stable directory-relative identity, start URL and scope. The app never installs itself; browser-owned installation requires a user gesture and confirmation. Offline launch reads saved history and defers live requests until reconnection.

## Verification

Run `npm run check`, `npm test`, and `npm run test:browser` on Node 22+. Tests cover destination and catalog injection, large/malformed responses, unsafe history, malicious metadata, CSP, deployment pins, local path traversal, host/origin spoofing, security headers, timing/math, GPS-free route selection, bounded parallel discovery, profile durations, loaded HTTP latency, cancellation, tab contention, storage failures/timeouts and legacy history. The real coordinator is exercised by a VM behavioral harness and three-browser synthetic end-to-end tests. PWA checks cover subpath resolution, icon dimensions and fallbacks, public asset MIME types, exact cache boundaries, failed installation, update fingerprints and scoped cleanup. Browser checks cover desktop and mobile layouts, keyboard tabs, exports, history, escaped record text, charts, popovers, dialogs, and CSP errors. Functional integration tests use synthetic traffic; they do not attack public speed-test providers.

## Limits and deployment decisions

- GitHub Pages serves HTTPS, but this repository cannot set arbitrary response headers there. Meta CSP works for supported directives; `frame-ancestors`, Permissions-Policy and X-Content-Type-Options need host/proxy response headers. Do not assume a `_headers` file or meta tag configures them on Pages. Recheck actual production headers after publishing. For stronger header control, a custom domain with a configurable edge proxy can be added later.
- The fallback anti-framing check is weaker than browser-enforced anti-framing headers. Treat response-header clickjacking protection on plain Pages as a hosting limitation, not a closed finding.
- GitHub project sites under the same `owner.github.io` origin share browser trust/storage boundaries. Only host mutually trusted apps on that origin; a dedicated custom domain provides a separate origin. History is local convenience data, not authenticated evidence. Another script with same-origin access or a malicious browser extension can tamper with it.
- Discovery probes up to eight candidates normally, or all reviewed candidates up to 40 in expanded mode, in parallel. Only the bundled catalog is used. Provider filters are applied before probing and remain effective during recovery; failed probes never become fictitious available fallbacks. The wider provider coverage does not add proxies, remote scripts, API keys or telemetry submission routes.
- An allowlisted third-party operator may be unavailable, compromised, or change its DNS. Browser/private-network restrictions still matter. Orbit has no server-side fetch/proxy route, but client-side allowlists do not constrain someone who edits their own browser code. Never treat browser controls as backend authorization.
- The account, GitHub Actions platform, browser, TLS, upstream hosts, and network are separate trust boundaries. No application code can guarantee those remain secure. Public provider terms and capacity still apply.
- GitHub is hosting the app assets only. Large test payloads go directly to speed-test operators, not through Pages or a repository API.

## Reporting

Use the repository's private vulnerability reporting feature if enabled. Avoid posting credentials, public-IP logs, precise locations, or exploit details in public issues. Test Orbit locally or on an explicitly authorized deployment; public test-server operators are not included in that authorization.

## Observatory interface and exports

The segmented views, route dialog and info popovers use DOM text nodes. The new UI and pure telemetry helper are local, allowlisted shell assets; no runtime framework or CDN was added. Saved history retains its validated schema and does not acquire IP/ISP/ASN/location fields. CSV quotes cells and prefixes formula-like text. Copy cURL resolves only reviewed catalog endpoints and prepares one ten-second-bounded GET probe; the browser never executes shell commands. Legacy catalog mappings are labelled, and live connection metadata is kept separate from inspected history.

## Local release assurance

See [launch readiness](docs/launch-readiness.md) for dated evidence, threat model, owners, remaining risks and acceptance gates. Gitleaks scanned all 49 existing commits and the working tree with redacted outputs; Semgrep scanned the deployed JavaScript and release scripts with telemetry disabled. Development packages are version/integrity locked and have a generated CycloneDX SBOM. GitHub Actions now requires unit/artifact checks, browser checks, secret/SAST/SCA scans and a CodeQL severity gate before packaging/deployment, and prepares provenance for a deterministic static archive. CodeQL, provenance, deployment protections and the workflow itself need execution in GitHub after the owner approves a push; local YAML parsing is not CI execution evidence. No SLSA level, SOC 2, ISO certification or penetration-test immunity is asserted.

The 80% branch gate covers shared calculation/telemetry/validation modules. Browser/coordinator behavior has scenario coverage; its complete branch coverage and physical-device behavior remain separate evidence gaps. Service-worker tests exercise cached offline navigation; in WebKit the local server is stopped to simulate network loss because request interception can bypass the worker. Handled WebKit network diagnostics during forced transport failure are recorded, and unhandled promise rejections still fail the suite.

Reproduce release evidence with `npm ci --ignore-scripts`, `npm run check:release`, `npm run test:coverage`, `npx --no-install playwright install chromium firefox webkit`, `npm run test:release`, `npm run test:browser`, `npm audit --audit-level=high`, and `npm run sbom`. Gitleaks 8.30.1: `gitleaks git --redact=100 --report-format=json --report-path=coverage/gitleaks-history.json` and `gitleaks dir . --redact=100 --report-format=json --report-path=coverage/gitleaks-working-tree.json`. Semgrep 1.178.0: `semgrep scan --config p/javascript --metrics off --disable-version-check --no-git-ignore --error --json --output coverage/semgrep.json dist scripts`. Install security tools from their official distributions and verify release checksums. The small live check is opt-in: `node scripts/probe-endpoints.cjs --live`; its one-network GET results do not establish upload, load capacity or operator permission.
